# 指标“覆盖与解读”

2026-09-12。将每项指标中的固定方向提醒、公式串与评分声明，改为一行覆盖信息和一段针对当前测量的模型解读。原始记录、知识卡、文献定位与解读审计记录折叠保存。

## 生成与证据约束

展开某项指标时，前端请求 `POST /api/searches/{id}/metric-reading`，只提交候选、阶段、指标和语言。后端先检查运行所有权，再核验候选、输入、面板、执行计划及质量回执哈希；逐记录明细也校验哈希和记录身份。模型看见的是服务器提取的事实，而非客户端提交的数值。

上下文包括当前及直接相关指标、逐被试值、实际执行条件、具体缺测原因，以及本次运行冻结的相关知识卡和来源。小型阈值曲线保留数值与阈值轴；大型数组仅提供明确标注的摘要，不允许据此描绘峰形或瞬态。历史运行未冻结知识库时不自动套用当前知识库。

一次新解读包含两次有界模型调用：先形成草稿，再对照相同证据检查推导、分母、阶段、阈值和冗余内容。两次使用同一配置模型，属于模型自我复核，不是独立专家验证。第二次输出必须通过引用枚举、当前指标引用、知识卡与来源匹配、缺测判断以及结构校验，否则不展示结论。自动检查不能保证每一句语义正确。

提示词要求只保留一段有信息量的判断，不凑竞争解释或建议。核查建议仅在能解决具体缺口时出现。不能从峰峰值与 MAD 的比值推断稀疏瞬态，也不能把不同阈值的超限率极值说成被试极值。

## 复用与追溯

解读独立保存在运行目录的 `metric-readings/{input_hash}.json`，不改写搜索决策、测量或评分。文件包含证据、来源、草稿、最终解读、生成时间、模型标识和提示词哈希。缓存键包含证据、生成及复核提示词、输出结构、模型配置和语言；相同输入在刷新或服务重启后复用已保存结果。每次读取缓存仍核验原始证据及保存内容。

同一服务进程内合并相同请求，同时最多处理两项；供应商调用关闭自动重试。失败时页面提供明确失败状态和重试入口，不用固定文案替代模型判断。切换候选、阶段、指标或语言时丢弃旧响应。

## 实测与验收

使用已有 EEGMMIDB 运行 `3d6d5daa63f24565a3bf46f5a416584a`，候选 `bp8-30-average`、处理后任务阶段，调用真实 `deepseek-v4-flash` 检查了 8 项解读：峰峰值、数值秩、平坦比例、50 Hz 工频比值、PSD、mu ERDS、通道相关和协方差条件数。没有重跑 EEG 预处理或训练。

检查过程中发现并纠正了两类问题：草稿从幅度统计量比值推断稀疏瞬态，以及只凭聚合缺失原因泛泛解释。最终上下文补齐阈值轴及关联指标的逐记录原因，并加入证据复核和引用枚举。人工抽查最终 8 项的数值、单位、阶段和缺测原因；这是一组真实样例验证，不等于证明所有未来生成均正确。

| 实例 | 核验事实与解释范围 |
| --- | --- |
| 数值秩 | 64 通道、已执行平均参考，数值秩 63；12 条记录协方差奇异。符合参考约束的代数预期，不能由此认定伪迹水平。 |
