# 有预算的离线预处理搜索

搜索入口是已完成数据接入与标准化的运行页中的「预算预处理搜索」，也可直接打开 `/searches?workflow=<运行编号>`。当前支持 EEGMMIDB 左右手运动想象。源运行的全部已接入被试进入搜索面板，默认按固定随机种子分成约 80% 训练被试和 20% 开发被试。页面可填写两组被试编号；显式分组必须无交集并覆盖全部接入被试。

搜索结果用于选择一个固定学习器在开发面板上表现较好的预处理方案。完整连续记录经离线处理后切窗；这不对应在线因果滤波，也不构成独立测试集上的泛化验证。

## 固定协议

开始搜索时冻结输入文件校验、被试分组、原始事件和 trial 清单、类别、通道顺序、输出 160 Hz 采样率、源运行的 epoch 窗口、软件环境、评价器及候选目录。至少需要两个被试，每个被试须有可评价的左右手试次。所有候选面对同一个预先确定的有效 trial 集；共同的越界窗口在面板中记录原因，候选不能自行删除困难试次。

每个 trial 每个通道计算对数方差，方差下限为 `1e-20`。StandardScaler 和 LogisticRegression 仅在训练被试上拟合，开发被试仅用于预测和评分。主指标先计算每位开发被试的 balanced accuracy，再对被试取平均。回执包含左右类召回、相对参考方案的逐被试差值、原始/有效/可用/已预测数量、方差下限使用情况、收敛诊断及耗时。缺失预测、标签或身份错配会使候选无效，不能缩小分母后继续参与排名。

有限目录包含四个频带 `8–30`、`1–40`、`4–40`、`8–40 Hz`，分别组合平均参考与原始参考，共八项。固定参考是 `bp8-30-average`。各项使用固定的 IIR 双向滤波、通道及 epoch 参数。LLM 不能新增代码、改变样本、替换分类器或引入 ICA 等另行拟合的操作。epoch 减常数不改变方差，因此不作为搜索维度。

## 搜索与预算

默认最多执行 6 个不同候选（包含固定参考）、接收 8 次提案、定向阅读 2 次、运行 3600 秒；整个搜索最多允许一次暂时性故障重试。内存和磁盘可手动设上限，留空时按启动时可用资源确定。时间从创建起计算，包含准备、数值执行、评价、模型调用、失败及中断停机时间；恢复不刷新截止时间。结束后的报告与文件索引导出单独进行。内存指标是对子进程 RSS 的采样，模型费用及供应商 token 消耗未计量。

| 策略 | 决策方式 |
| --- | --- |
| 逐轮反馈 `adaptive` | 先执行参考；LLM 每轮读取真实评价与剩余预算，选择候选、定向阅读或结束 |
| 一次性提案 `one_shot` | 在参考评分出现前由 LLM 冻结候选顺序；之后不再按结果重排 |
| 随机 `random` | 按固定随机种子生成顺序，在相同预算内执行 |
| 枚举 `exhaustive` | 按冻结的目录顺序执行，在预算处停止 |

LLM 的动作受 JSON Schema 约束。候选提案须包含已评价的父候选、理由、预期以及改善/未改善后的选择分支。定向阅读针对源运行已保存并冻结的文献、官网资料，记录问题、检索短语、精确摘录及它影响的选择；不会重新搜索互联网。无效与重复提案也占用提案预算。模型不能自行填写评价分数。

若全部剩余组合可在候选、时间和磁盘预算内经济地完成，逐轮策略可转为枚举并记录原因。预算是上限，允许模型提前结束。固定参考失败则停止；执行或资源故障不会被记成零分。达到预算、耗尽候选、模型结束或冻结协议失效时停止。

选取所有有效候选中开发主指标最高者；精确平局依次优先固定参考、算子更少者、目录中更靠前者。结果仍需独立确认；跨策略比较应保持相同源输入、被试角色、随机种子和预算，不能把开发分数直接当作研究结论。

## 过程文件

所有内容保存在后端工作目录的 `offline-search/<搜索编号>/`，由现有 `workspace/` ignore 规则排除出 Git。页面分开展示概览、候选比较、决策轨迹和文件；报告由结构化回执生成。

| 文件 | 内容 |
| --- | --- |
| `protocol.json` / `limits.json` | 冻结的输入、方法目录、评价与资源协议 |
| `input.json` / `panel-request.json` | 标准化输入和面板建立参数 |
| `panel.json` | 被试角色、记录身份、逐 trial 清单及共同无效原因 |
| `search.json` | 累计预算、动作及候选状态，不因恢复重新计数 |
| `sources.json` | 可定向阅读的冻结来源 |
| `format.schema.json` | 搜索状态、面板和评价回执的结构定义 |
| `candidates/<编号>/method.json` / `plan.json` | 固定操作与编译后的数值方案 |
| `candidates/<编号>/result.json` / `receipt.json` | 数值任务结果和评价反馈 |
| `candidates/<编号>/predictions.tsv` | 开发 trial、原始事件、真实标签和预测的对应 |
| `selection.json` / `report.html` | 选中方案、停止原因、候选比较与结论范围 |
| `files.json` | 全部产物的下载定位、大小和校验，包括数值数据文件 |

每个候选使用独立数值任务，已完成记录可复用。恢复前重新核对冻结内容、实际源文件及已保存方案/数值产物/回执；不一致时终止该搜索。取消会终止其工作子进程。应用重启可恢复未完成搜索，预算与失败历史保留。

## API 与命令行

`POST /api/searches` 创建；`GET /api/searches` 列表；`GET /api/searches/<id>` 查询；`POST /api/searches/<id>/cancel` 取消；`POST /api/searches/<id>/retry` 在剩余预算内恢复；`GET /api/searches/<id>/artifacts/<path>?download=true` 下载。使用与工作流相同的 owner 身份。

后端安装 EEG 可选依赖并启动 API 后，在 `backend/` 下执行：

```bash
python -m app.search --workflow <运行编号>
python -m app.search --workflow <运行编号> --strategy random --max-candidates 6 --max-seconds 3600
python -m app.search --resume <搜索编号>
```

可用 `--train-subjects S001 S002 S003 --development-subjects S004 S005` 显式冻结分组；`--no-wait` 仅提交任务。网页结果地址为 `/searches?id=<搜索编号>`。
