# 诊断驱动的预处理策略搜索

数据接入完成后，工作流自动运行预算搜索，按开发评价选择共享处理策略，并将实际评价过的数据表示交付给训练。运行页中的搜索入口显示同一个搜索的预算、候选、诊断、预测核对与记录。独立创建搜索用于对照实验，不会改写已有运行。

## 决策对象

选择对象是一条可以应用于新被试的共享规则，包括固定信号处理、个体拟合权限、条件判断及输出表示。个体参数从各自无标签整批信号拟合，不从该人的评分标签中选择最优流水线。所有候选在相同任务、试次清单、输出网格和共同学习器下比较。

| 策略 | 每位被试的处理 | 输出 |
| --- | --- | --- |
| 公共处理 | 固定带通与参考，不拟合个人变换 | EEG 电压，V |
| 统一尺度 | 个人平均协方差的平均通道方差用于等比例缩放 | 原通道坐标中的无量纲表示 |
| 统一 EA | 个人平均协方差经正则化后求对称逆平方根 | 原通道坐标中的无量纲线性表示 |
| 条件 EA | 协方差各向异性达到冻结阈值时对齐；否则仅统一尺度 | 所有被试保持相同单位和坐标约定 |

EA 基于 [He 与 Wu 的无标签数据对齐研究](https://arxiv.org/html/1808.05464v2)。本实现使用 0.1 球形收缩稳定协方差；这是明确的实现参数，并非对论文原始数值结果的复现。条件指标为按平均方差归一化、收缩后的协方差特征值 Q90/Q10，以降低参考零空间和信号单位的影响；有效秩独立记录。阈值 3/10 是待比较的工程假设，不是已验证的伪迹诊断界限。对齐程度本身不参与胜者评分；是否有用由共同分类任务决定。空间变换不能当作原电极电压解释。

候选目录目前包含四个频带（8–30、1–40、4–40、8–40 Hz）：每个频带有平均参考、保留采集参考、统一尺度、统一 EA、两种阈值的条件 EA，共 24 条共享策略。个体适配均在保留采集参考的带通输出上进行。固定参考为 8–30 Hz＋平均参考。目录与参数来源在启动时冻结，模型不能写入任意代码或悄悄扩大搜索空间。

## 数据权限与评价

默认按固定种子将源工作流全部已接入的任务被试分为 `min(5, 被试数)` 折。每位被试恰好产生一次折外预测；同一个人的全部 Run 保持在同一折。五折是计算量与训练数据覆盖的工程默认，不宣称最优。至少需要两位具备有效左右手试次的被试。显式指定训练与开发组时，两组必须互斥且覆盖全部接入被试。

每折仅使用训练被试标签拟合 CSP（最多四个分量，协方差收缩 0.1）和收缩 LDA。主分数是每位开发被试的左右手平衡准确率，再对被试等权平均。相同数据另外计算对数方差＋标准化＋逻辑回归作为次要对照，模型不能改用该对照成绩决定胜者。计算流按 epoch 流式读取，协方差暂存磁盘，避免将全部 EEG 数组装入内存。

个体适配可以访问该人整批无标签试次，属于离线转导协议；目标标签仅用于折外计分。共同无效窗口在候选执行前确定；候选必须完整覆盖共同有效试次，不得通过丢弃难例提高分数。处理适配、分类器拟合和评分分别保存范围。

这些折外分数反复用于策略搜索，因此是开发成绩。被试配对差值的 bootstrap 区间仅描述当前开发样本，不消除搜索偏差和折间依赖，不表示独立确认。最终独立确认需要未用于策略开发的数据；当前工作流不把已有开发数据重新命名为独立测试集。

## 观察、预测与修订

模型接收采集与调研资料、全部实测候选的紧凑回执、覆盖全部被试的诊断摘要、逐被试评分与配对表现和剩余预算。完整通道诊断及表示文件索引保存在数值回执中。每次自适应提案必须满足结构合同：

1. 引用已完成候选及实际存在的数值指标路径。
2. 给出当前解释与竞争解释。
3. 实验前分别登记信号预测和效用预测，包含指标、方向、容差与依据。
4. 说明什么结果会削弱解释，改善或未改善将怎样改变下一步。

控制器在运行前拒绝虚构观察路径。实验后程序逐项比较父候选与新候选的实测值，记录符合、未满足预测条件或不可测量。执行失败不被计成零分或反证。信号预测失败而效用改善时可以保留候选，但不能把原解释写成已证实的原因。数值回执保存每位被试的通道方差、平坦比例、处理前后协方差条件数、适配决定及拟合试次数。

这里的 before/after 指个体适配之前/之后；before 已经过带通、参考和切窗。诊断总体摘要对全部被试等权计算，模型所见字段与回执路径一致。

| `diagnostics.summary` 字段 | 含义与解释边界 |
| --- | --- |
| `mean_condition_before` / `mean_condition_after` | 适配前后协方差条件数的被试均值。归一化后使用相对特征值下限；参考产生的零空间也会使条件数变大，不能直接等同于噪声。 |
| `mean_variance_before` / `mean_variance_after` | 每位被试平均通道方差的总体均值。电压表示的方差单位是 V²；适配后可能无量纲，必须结合 representation 解释。 |
| `mean_effective_rank` | 适配前协方差有效秩的被试均值，逐被试记录另含前后两个有效秩。 |
| `mean_anisotropy` | 适配前、归一化收缩谱 Q90/Q10 的被试均值，用于描述条件门控输入；不表示 EA 后的各向异性。 |
| `gate_fraction` | 条件策略实际触发对齐的被试比例。非条件策略为 null，不能当作零触发。 |

预测的 `tolerance` 是所引用指标单位下的绝对容差：increase 要求 `after - before > tolerance`，decrease 要求小于负容差，unchanged 要求差值绝对值不超过容差。`contradicted` 表示未满足这项提前登记的数值条件，也包括变化幅度未超过容差；它不自动区分解释错误、指标阶段选择不当或容差不合适。机制解释仍需结合这些边界审阅。

`request_evidence` 定向阅读冻结资料；`finish` 保存停止理由和未决问题。当前 LLM 使用结构化数值而非直接读图。跨任务知识学习、在线适配、标签校准和独立确认实验不由这条离线协议隐式承担。

## 预算与选择

默认最多评价 6 个候选（含参考）、接收 8 次提案、读取 2 次资料、运行 3600 秒；暂时故障全程最多重试一次。内存和磁盘可配置，留空按启动时可用资源确定。预算包含数值计算、模型调用、失败与停机时间；恢复不重置预算。单次提案对照先冻结顺序；随机对照只随机尝试顺序；枚举对照按目录执行。全部剩余组合预计可在预算内完成时，自适应控制器可以转为枚举。

最终选择实测有效候选中主分数最高者。精确同分优先固定参考、再按算子数及目录顺序决定。模型不直接指定胜者。结果解释为当前开发条件下选出的共享策略，不能解释成每个人的最佳参数或生理质量认证。

## 产物与训练交付

| 文件 | 内容 |
| --- | --- |
| `protocol.json`、`limits.json` | 输入、策略目录、评价与权限、参数来源、资源预算 |
| `panel.json` | 被试折、原始 trial、共同有效范围与输出网格 |
| `search.json` | 当前状态、累计预算、动作、候选与停止原因 |
| `sources.json` | 已冻结的官网及文献资料 |
| `decisions/<轮次>/request.json`、`response.json` | 实际模型输入和结构化答复 |
| `candidates/<编号>/policy.json` | 共享策略、参数与个体适配规则 |
| `candidates/<编号>/method.json`、`plan.json`、`result.json` | 连续信号处理、编译计划和数值执行 |
| `candidates/<编号>/receipt.json` | 两个共同学习器、折外成绩、诊断、配对差和表示索引 |
| `candidates/<编号>/originalpredictions.tsv` | 原始试次、折号及主次评价器的预测 |
| `candidates/<编号>/adaptation/` | 各人变换矩阵及实际用于评分的适配数组 |
| `selection.json`、`report.html` | 选中策略、依据、比较与适用范围 |
| `files.json` | 全部产物下载位置、大小与校验 |

工作流交付数组取自选中策略的实际表示，附带单位、变换矩阵、来源、评价协议和折清单。交叉验证开发面板导出为可训练数据，独立测试计数为零；显式留出模式保留训练与开发角色。既有运行按自身保存的文件阅读，执行时核对冻结代码与格式。

生成数据、搜索日志、预测和拟合矩阵位于 `backend/workspace/`，由 Git ignore 排除；源码、Schema、测试与当前使用说明纳入版本控制。

## 接口

主入口为 `/workflows`。独立搜索使用 `/searches?workflow=<运行编号>`，已关联搜索为 `/searches?id=<搜索编号>`。

`POST /api/searches` 创建，`GET /api/searches/<id>` 查询，`POST /api/searches/<id>/cancel` 取消，`POST /api/searches/<id>/retry` 在剩余预算内恢复。工作流请求的 `search_budget` 配置自动搜索预算。直接调用示例：

```bash
python -m app.search --workflow <运行编号> --max-candidates 6
python -m app.search --workflow <运行编号> --strategy random
```
