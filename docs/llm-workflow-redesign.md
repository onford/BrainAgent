# LLM 驱动的数据流程

## 审阅结论

原工作流 `WorkflowService.execute_stage` 将六个领域 Agent 转接到本地函数。
Survey 的在线模型检索循环仅用于独立对话，完整运行时被提前分支绕过；
预处理直接复制两组频带预设；报告只有模板和数值表。
因此，六模块运行成功只能证明数据转换与数值执行闭环，不能证明完成了资料调研或模型方案设计。

## 职责和执行顺序

1. 本地适配器扫描实际文件，提供元数据、事件、统计和已知适配规则。
2. 调研 Agent 分别规划数据核对和方法文献两条路线。数据核对比较本地实际文件、官网/仓库、官方数据集论文；方法文献区分分析使用、算法使用、讨论数据集本身、同类数据预处理，每种用途都覆盖 paper 和 repo。两条路线共用检索/阅读工具，目标、完成条件和输出分开。
3. 模型每轮提交 1–4 个独立任务并发执行。数据核对最多 12 个动作，方法文献最多 32 个动作，逐项保留读取失败和未覆盖目标。结束前检查各目标是否执行了对应的检索和阅读尝试；最终覆盖表只有“已读取且通过筛选”的资料才能填为已覆盖，检索过不等于覆盖完成。
4. 接入 Agent 核对论文/官网与所选记录的任务、Run、Trigger 语义。证据编号通过模型输入 Schema 中的枚举约束。未知映射触发补充阅读/检索，取得证据后再次核对；三轮后仍有冲突则阻止转换。范围外任务和非阻塞未知信息不作为不兼容条件。MNE/BIDS 转换和原文件保护由代码执行。
5. 预处理 Agent 从可执行算子目录设计 2–3 个不同候选，定义顺序、依赖、参数、输出和每步依据。模型面对的 Schema 按算子区分参数类型；通道与事件使用上游数据绑定，训练窗口由用户输入固定，不能由模型另写一份互相冲突的值。资料不足时可提出结构化补充检索/阅读请求，取得新证据后重新设计；补充结论保存在预处理目录，Survey 已完成记录保持原样。编译器绑定真实数据、校验参数和依赖、排除重复方案；失败原因反馈给模型。补充与修订最多三轮，仍无法执行时明确失败。
6. Worker 执行冻结计划，保存实际参数、事件映射、统计和中间产物。已经提交的数值任务在重启后沿用，不因模型重试重跑。
7. Evaluation 仍通过完整性条件筛选后随机选取；Delivery 仍确定性对齐数组、标签和分组并打包。两者不需要模型代替可验证计算。
8. 报告 Agent 用 LLM 形成数据解释、方法依据和限制；报告从固定结构化记录和实际统计填入 HTML 模板。

## 固定过程文件

| 路径 | 内容 |
|---|---|
| `survey/research-plan.json` | 问题、分类和查询计划 |
| `survey/directory-tree.txt`、`survey/local-inspection.json` | 实际目录层级，以及所选记录的文件头、数组形状/类型/有限性、通道、事件、采样率和时长观测 |
| `survey/sources.json` | 实际检索动作、读取正文、URL、获取时间和来源字节哈希 |
| `survey/verification.json` | 13 类字段的本地/官网仓库/官方论文三方对比；官方论文身份、引文、元数据、缺口和冲突 |
| `survey/literature.json` | 四种用途 × paper/repo 的八格覆盖、纳入/排除/待补充理由、原文、链接和有来源的参考指标 |
| `survey/research.json` | 为既有数值流程派生的兼容视图；数据核对和文献筛选的权威记录为前述两个独立文件 |
| `collection/review.json` | 任务和标签的适用性核对 |
| `collection/research.json`、`collection/sources.json` | 接入核对阶段补充调研的结论与来源（发生时生成） |
| `preprocessing/design.json` | 模型方案、参数、依赖及每步依据 |
| `preprocessing/revisions.json` | 编译拒绝及修订历史（发生时生成） |
| `preprocessing/research.json`、`preprocessing/sources.json` | 方案设计阶段补充调研的结论与来源（发生时生成） |
| `report/narrative.json` | 固定报告章节的解释文字 |
| 各模块 `decisions.json` | 模型名、决策输出、接受/拒绝/失败记录 |

所有文件使用 Pydantic 契约校验，并列入 `process/schema.json` 和 `process/formats.json`。
格式版本为 3。历史已完成运行保持原文件；格式变化后的未完成旧运行需要新建，不能重写历史格式。
模型输出不作为 Python 代码执行，也不能自行声明方法经过科学验证。

## 并发阅读

采用异步工具并发读取、主 LLM 统一归纳的方式。每批最多 4 个任务、同一工作流最多同时执行 4 个资料任务；单个任务等待上限 90 秒。预处理方案提出的补充阅读列表也并发执行。接入核对中依赖上一步结果的补充动作仍逐步选择。

`ResearchBatch` Schema 限定每批数量、拒绝重复动作，并禁止把 `finish` 与其他任务混在一批。两条路线分别计数，按单个动作而非批次数计数。模型提交的一批动作保存在 `decisions.json` 的 `result.actions`；逐任务结果在 `sources.json` 中标注 `purpose`、`target` 和 `medium`，分别说明核对/文献用途、具体目标、paper/repo 等资料类型。

## 数据核对与文献用途

本地观测由代码从实际文件生成，模型只能引用观测编号；三方对比中的官网和论文陈述必须有可匹配原文的证据。缺一方时不能写为三方“一致”。采集系统论文、普通使用论文不能自动视为官方数据集论文；未确认身份时保留空列及说明。

文献筛选的固定标准是相关性、内容充分性、可追溯性，并优先检索可信期刊、高被引论文和高星仓库。期刊、被引数、星标必须匹配相应检索结果；缺失为 null，不虚构质量分数或引用阈值。摘要资料可保留为待补充，不能直接纳入方法依据。已读来源的 PDF/repo 关联链接从来源及对应检索条目中取得。

使用数据集的分析和算法资料对应 3.2/3.4（使用关系待讨论）；数据集本身的讨论对应 2.3，提取论文报告的被试/Run 等排除信息供接入核对；同类数据预处理资料对应 3.2。接入与方法设计收到各自用途的已纳入条目。文献中的排除建议属于带来源的待核对信息，不直接执行为本地数据删除命令。报告分别呈现三方对照和方法文献覆盖/筛选表。

每个任务完成即保存来源与结果，按分配顺序编号；失败、超时分别记录，其他任务继续。取消运行时会取消并等待剩余读取任务退出，已经保存的成功结果供重试复用。后台读取不会在阶段停止后继续写入记录。

2026-09-09 验收运行 `34614c3b791649f7965faaca515686fc`：真实模型安排了 4 批各 4 个任务，然后结束调研；其中一批包含 4 个同时读取的来源。16 个工具任务中 11 个成功、5 个失败，均保留独立结果。最终汇总引用官网、MNE 文档及两篇论文资料，产生 17 条可匹配原文的事实；论文阅读范围均标为部分正文。

联调同时修复了接入判断中“兼容但存在阻断冲突”的自相矛盾输出，以及候选 `output` 字段被误填为说明文字的问题。前者通过语义校验要求模型重新区分阻断冲突与非阻断元数据备注；后者由模型面对的 Schema 限制步骤编号格式，编译器列出允许的实际步骤编号。已有数据标签和科学计算检查继续保留。

修复后从失败阶段重试，全部阶段完成，交付数组为 `90 × 64 × 321`，训练/验证/测试各 30 条且被试互斥。25 个辅助 JSON、7 个 TSV、格式版本 2、6 个原始 EDF 哈希及交付清单中的 31 个文件哈希通过核验；训练示例完成拟合和 90 条预测。28 项工作流测试通过，覆盖并发上限、部分失败、超时、取消后保存、动作预算、结构校验及数值流程。

## 运行边界

当前本地读写适配器只支持 EEGMMIDB 左右手运动想象。研究与方法设计框架可复用，但其他数据集的解码、事件规则和标准转换仍需要适配器。
首次运行要求配置 LLM 和至少一个可用论文检索集成。模型调用失败不会降级成固定预设。
官方 DeepSeek 接口的工作流推理强度默认 `low`，通过 `WORKFLOW_REASONING_EFFORT=low/high/max` 配置，对话模型配置独立；参数依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
最低检索覆盖不代表穷尽文献；摘要、部分正文与完整正文必须区分，原文存在校验不能替代人工科学审阅。
自动方案限于已启用算子；质量排名、复杂异常治理和完整文献复现实验仍未实现。
