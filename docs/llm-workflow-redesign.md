# LLM 驱动的数据流程

## 审阅结论

原工作流 `WorkflowService.execute_stage` 将六个领域 Agent 转接到本地函数。
Survey 的在线模型检索循环仅用于独立对话，完整运行时被提前分支绕过；
预处理直接复制两组频带预设；报告只有模板和数值表。
因此，六模块运行成功只能证明数据转换与数值执行闭环，不能证明完成了资料调研或模型方案设计。

## 职责和执行顺序

1. 本地适配器扫描实际文件，提供元数据、事件、统计和已知适配规则。
2. 调研 Agent 通过 LLM 形成问题清单，覆盖官网、使用数据集的论文、讨论数据集的论文、预处理方法。模型选择检索工具和阅读地址，工具返回公开 HTML/XML/PDF 正文及链接。模型据此继续检索或结束。
3. 结构化调研结论引用已读取来源和原文片段。代码核验引用身份、原文匹配和最低检索覆盖。无法阅读的全文与尚缺资料保留为缺口。
4. 接入 Agent 核对论文/官网与所选记录的任务、Run、Trigger 语义。证据编号通过模型输入 Schema 中的枚举约束。未知映射触发补充阅读/检索，取得证据后再次核对；三轮后仍有冲突则阻止转换。范围外任务和非阻塞未知信息不作为不兼容条件。MNE/BIDS 转换和原文件保护由代码执行。
5. 预处理 Agent 从可执行算子目录设计 2–3 个不同候选，定义顺序、依赖、参数、输出和每步依据。模型面对的 Schema 按算子区分参数类型；通道与事件使用上游数据绑定，训练窗口由用户输入固定，不能由模型另写一份互相冲突的值。资料不足时可提出结构化补充检索/阅读请求，取得新证据后重新设计；补充结论保存在预处理目录，Survey 已完成记录保持原样。编译器绑定真实数据、校验参数和依赖、排除重复方案；失败原因反馈给模型。补充与修订最多三轮，仍无法执行时明确失败。
6. Worker 执行冻结计划，保存实际参数、事件映射、统计和中间产物。已经提交的数值任务在重启后沿用，不因模型重试重跑。
7. Evaluation 仍通过完整性条件筛选后随机选取；Delivery 仍确定性对齐数组、标签和分组并打包。两者不需要模型代替可验证计算。
8. 报告 Agent 用 LLM 形成数据解释、方法依据和限制；报告从固定结构化记录和实际统计填入 HTML 模板。

## 固定过程文件

| 路径 | 内容 |
|---|---|
| `survey/research-plan.json` | 问题、分类和查询计划 |
| `survey/sources.json` | 实际检索动作、读取正文、URL、获取时间和来源字节哈希 |
| `survey/research.json` | 归纳结论、逐条引文、论文阅读范围、缺口与冲突 |
| `collection/review.json` | 任务和标签的适用性核对 |
| `collection/research.json`、`collection/sources.json` | 接入核对阶段补充调研的结论与来源（发生时生成） |
| `preprocessing/design.json` | 模型方案、参数、依赖及每步依据 |
| `preprocessing/revisions.json` | 编译拒绝及修订历史（发生时生成） |
| `preprocessing/research.json`、`preprocessing/sources.json` | 方案设计阶段补充调研的结论与来源（发生时生成） |
| `report/narrative.json` | 固定报告章节的解释文字 |
| 各模块 `decisions.json` | 模型名、决策输出、接受/拒绝/失败记录 |

所有文件使用 Pydantic 契约校验，并列入 `process/schema.json` 和 `process/formats.json`。
格式版本为 2。历史已完成运行保持原文件；格式变化后的未完成旧运行需要新建，不能重写历史格式。
模型输出不作为 Python 代码执行，也不能自行声明方法经过科学验证。

## 运行边界

当前本地读写适配器只支持 EEGMMIDB 左右手运动想象。研究与方法设计框架可复用，但其他数据集的解码、事件规则和标准转换仍需要适配器。
首次运行要求配置 LLM 和至少一个可用论文检索集成。模型调用失败不会降级成固定预设。
官方 DeepSeek 接口的工作流推理强度默认 `low`，通过 `WORKFLOW_REASONING_EFFORT=low/high/max` 配置，对话模型配置独立；参数依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
最低检索覆盖不代表穷尽文献；摘要、部分正文与完整正文必须区分，原文存在校验不能替代人工科学审阅。
自动方案限于已启用算子；质量排名、复杂异常治理和完整文献复现实验仍未实现。

## 实际验收（2026-09-08）

运行 `87f0cc40a92d4db09f47eec36837d0ef` 使用真实 `deepseek-v4-flash` 接口和本地 EEGMMIDB 的 S001–S003、Run 4/8。联调中修复引用换行匹配与算子绑定 Schema 冲突后，通过重试完成六阶段；没有用测试模型替代真实调研或方案设计。

- 实际读取 PhysioNet 官网、MNE Run 映射文档及一篇运动想象论文摘要。已尝试检索使用数据集、讨论数据集、预处理论文三个分类，另检索公开代码；形成 8 条可匹配原文的事实。未读到相关方法全文，具体参数仍有工程决策成分。
- 模型生成并执行三个候选：“标准带通与全段基线”“宽带去趋势无基线”“运动想象窄带与坏道检测”。种子 42 随机选中第二个。没有计算质量排名。
- 交付 `float32` 数组为 `90 × 64 × 321`，左右手标签数为 46 / 44，训练、验证、测试各 30 条且被试互斥。6 个源 EDF 文件哈希保持一致。
- 逐一下载 368 个产物，共 136,081,827 字节；核对可用链接、已有 SHA-256 和 ZIP 内清单。主阶段记录、23 个辅助 JSON、7 个 TSV、数组类型和格式版本 2 均通过校验。
- 数据包内训练示例完成拟合与 90 条预测，拟合仅使用训练组 S002。此检查证明训练接口可用，不构成模型效果评估。
- 后端 97 项测试通过；前端 15 项测试、类型检查与生产构建通过；新增代码通过 Ruff。浏览器实查完成页、报告、文件概要和折叠分组。

报告由真实模型生成，引用存在性校验尚不能保证所有自然语言解释正确。例如本次报告限制段仍将早期的“通道数未核验”疑问带入最终文字，而本地记录已经验证了通道数；应以结构化记录及实际统计为准，科学解释仍需审阅。
