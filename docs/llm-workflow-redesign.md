# LLM 与数值执行的职责

数据调研分别核对本地文件、官网/仓库与官方论文，并检索使用数据集、讨论数据集和讨论同类预处理的资料。实际文件信息由代码测量，来源陈述由模型对照与筛选；引文、任务标签和排除依据经过结构与语义校验。

接入阶段将可读取文件标准化，保持源数据不变，核对任务标签及共同训练接口。源目录的全部被试与 Run 进入调研与接入清单；左右手运动想象训练仅使用任务含义核验通过的对应记录，其他任务保留在接入清单中。

预处理阶段自动运行[诊断驱动的策略搜索](offline-preprocessing-search.md)。LLM 提出解释、竞争解释和可检验的实验预测，选择下一条共享处理策略或补读证据；数值工具负责实际变换、训练、折外预测、诊断与预测核对。选中结果由固定开发评分规则确定，并作为报告与训练交付的唯一输入。

报告从固定结构化记录填入模板。模型补充方法依据和限制，不覆盖程序生成的数值表、处理顺序、数据单位或评价范围。各类失败保持独立：资料缺口、数据不可评价、候选无效、执行故障和资源不足。

## 资料阅读

调研工具每批最多四个并发任务，逐项记录来源、正文、定位和错误，主模型统一比较。Schema 禁止重复动作及将 finish 与其他动作混用。来源记录中的 purpose、target 和 medium 说明核对/文献用途与资料类型。未读正文或来源不支持的结论不能成为方法证据。

搜索器只读取启动时冻结的资料快照，围绕可能改变决策的问题补读；其模型输入不包含独立确认数据。全部候选输出和诊断保留适用条件，经验先验不作为永久淘汰未尝试方案的依据。
