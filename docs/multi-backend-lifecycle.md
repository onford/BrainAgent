# 多后端所有权、停止与恢复

2026-09-13，剩余修改第29批（I33）。所有后端共享同一运行目录时，工作流持有 `workflow.lock`，搜索持有 `search.lock`，锁覆盖重新读取状态、实际执行、取消排空和终态发布。抢不到锁的后端只返回已有状态。完成的搜索不会被重复执行或重新发布。

搜索停止请求保存为 `run-control-1` 的 `control.json`：请求 ID、所有者、时间、恢复代次和追加历史。另一后端通过原子文件读取观察停止请求，中断当前等待；请求被接受时仍显示“正在停止搜索…”，待拥有者排空并保存终态后显示已取消。无活动拥有者时，获得搜索锁的后端才可直接完成取消。读取历史控制状态不创建文件；越权请求先被拒绝。

恢复先取得同一执行锁，校验原代码、环境、预算与状态，之后增加恢复代次、清除待处理请求并保留历史。截止时间、已用模型调用、候选开销不重置；已结束运行的旧内存取消标志不能取消新代次。控制文件损坏导致失败和停止，不继续等待，也不发布赢家。

线程操作无法靠取消 asyncio 协程来终止。来源检查、数据观察、标准化、报告/交付、搜索诊断等阻塞操作现在被屏蔽直接取消，并在原线程退出后释放拥有者锁。标准化收到协作取消标记。长时间不响应取消的第三方阻塞操作仍可能延迟退出；此时保持锁，不能声称已停止，也不允许另一个后端并行改写。数值原生进程的强制终止/父进程死亡保护见 [原生生命周期](native-lifecycle-and-recovery.md)。
