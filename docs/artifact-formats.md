# 产物格式约定与检查结果

同一种产物使用固定的文件类型、路径规则、字段含义、类型和组织方式。文件数量、被试/Run 编号、时间、统计值和数组轴长度属于数据内容，可以随运行变化。成功与排除记录使用 Schema 中明确声明的分支；可选字段也以 Schema 为准。

## 格式约定

| 产物 | 固定部分 | 可变部分与验证方式 |
|---|---|---|
| 六个模块主记录 | JSON 路径和 Pydantic 模型 | 被试、记录列表、统计和来源；发布前拒绝缺失必需字段、额外字段和非法引用 |
| 接入统计、输入快照、预处理计划/结果、报告数据、训练元数据 | `formats.py` 中的 JSON 模型 | 内容可变，写入前校验，保留模型声明的默认字段 |
| 项目生成的 7 类 TSV | UTF-8、制表符、LF 换行、固定列名/顺序/类型 | 行数可变；空表仍写表头；缺列、多列、错列序均报错 |
| `X.npy` | float32，Trial × 通道 × 时间点，单位 V | 各轴长度随选定数据与参数变化 |
| `y.npy` | int64，一维，0=左手、1=右手 | 每行与 X 对齐 |
| `subjects.npy` | NumPy `<U4`，一维 | 每行保存 S001 形式的被试编号 |
| `split.npy` | NumPy `<U10`，一维 | train / validation / test；单被试时也保持相同 dtype |
| 交付清单 | 固定字段、两类标签计数和三组分组计数 | 没有样本的类别/分组写 0 |
| HTML 报告 | 固定 HTML 模板与结构数据映射 | 仅填充本次数据；模板指纹记录在格式清单中 |
| 训练 ZIP | `DELIVERY_FILES` 与逐记录 `PROVENANCE_FILES` 清单 | 记录数量可变；模块回执及上次遗留文件不会混入包内 |
| BIDS / BrainVision 副本 | 由固定版本 mne-bids 输出标准格式 | 被试、任务、Run 等实体决定文件名；本项目还未运行完整官方 BIDS Validator |
| Worker 的 FIF、NumPy 和诊断 JSON | 数值执行器及具体操作的输出约定，执行计划固定实现版本 | 各操作的参数、模型和中间数组不同；底层诊断 payload 尚未全部转换为统一的严格 Pydantic 模型 |

主记录的具体路径见 [训练流程说明](training-workflow.md)。JSON 字段顺序不用于表达业务语义；TSV 列顺序、数组轴顺序及事件行对齐必须稳定。

## 格式版本与追溯

文献筛选的运行时 Schema 使用来源绑定的 `passage_id` 选择原文片段，ID 包含来源、内容指纹及字符范围；每个条目的 `source_id` 必填。模型只生成筛选判断和结论，程序补入该片段的原文、来源 ID，以及成功检索结果中实际取得的期刊、引用数和星标；未取得的指标为 null，实际取得的 0 保留为 0。片段不得跨来源引用，正文预览不能标为全文。

`survey/decisions.json` 保留模型所选片段 ID，`survey/literature.json` 和 `survey/research.json` 继续使用原有 Finding 字段，保存展开后的 `source_id` 与 `quote`；既有产物 Schema 和格式版本不变。筛选失败后的重试从该决策继续，复用已保存的来源与检索缺口，不重新开始整轮检索。

新运行的 `process/formats.json` 列出 JSON 的 Schema 引用、TSV 行结构、数组类型和报告模板 SHA-256，并保存 `process/schema.json` 的 SHA-256。格式清单当前版本为 `4`，区别于调度状态文件的存储版本。版本 4 新增接入检查、文献排除对象匹配、完整事件/通道映射和带原因的筛选统计；上下文事件与训练事件分开。未知统计使用 JSON null 或 TSV 空数值。版本 3 将数据信息三方核对与方法文献筛选分开，新增本地实际观测、三方对比、八格文献覆盖及筛选契约，并给检索动作记录用途。旧运行可继续查看，未完成的旧格式运行需新建或用原代码继续。详见 [模型工作流设计](llm-workflow-redesign.md)。

阶段执行和主记录发布前核对格式快照。发现 Schema、数组约定或报告模板变化时，阻止在同一次运行中继续混写；应新建运行，或者用原代码版本续跑。已有快照不会静默替换。后续修改格式需更新约定和版本，说明兼容或迁移方式。

旧运行没有这份格式清单时继续提供历史文件入口，不能据此认定其已通过新增的格式检查。
