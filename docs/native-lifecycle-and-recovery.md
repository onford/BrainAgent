# 原生进程中断与任务恢复

实际 MATLAB R2025b/RELAX 已在固定真实 S001R04 桥接输入上验证三种停止路径：进入原生信号滤波后取消、30 秒原生进程超时、强制结束 Python 执行器。第三次完整实测分别耗时 13.422、34.813、10.062 秒；各次捕获的本次进程内核句柄均确认退出，原输入和原生依赖不变。只观察本测试创建的进程，不结束其他 MATLAB 实例或服务。

正常取消和超时保存 `cancelled` / `timed_out` 回执。执行器被强制终止时，其最后一次原生回执可能仍为 `running`，但 `completed=false`；不会将缺少完成写入解释为成功。前两次监测脚本因 Windows 同一进程编号文件的读写冲突而失败，第三次改用不可变的进程集合快照；失败证据保留，生产算法没有为通过测试而改动。

新 worker 获得独占 OS 锁后，对确实处于 running 的记录保存 `worker-recovery-1` 回执，再将状态转为 interrupted，并清除残留结果引用。回执绑定 job、record key、attempt 和原生回执哈希，保留原生最后声明；不重写原始执行日志。不通过心跳超时推断锁拥有者死亡，不接受旧输出，也不单凭取得 worker 锁宣称每个原生 PID 已退出。损坏的计划不用于猜测产物路径，也不阻塞其他任务的恢复。

中断的当前尝试和等待决定的停止尝试可在工作流产物列表中查看；后续重试使用新 attempt。已完成记录仍按完整结果验签后保留。

真实工作任务实测使用同一 RELAX 配方处理 S001R04 与 S002R04：第一条记录完成，第二条进入滤波后强制结束 worker。重启后第一条保持 attempt=1，第二条完成 attempt=2；第一条完整产物与第二条原生旧回执均未变，中断回执可访问。总耗时 171.172 秒，输入及冻结代码不变。第一次驱动错误地将 API 按内部 key 排序的列表当成计划顺序，导致断言失败；第二次改为按 record_id 核对，完整实测通过。

最终 44 项恢复/worker 失败/原生进程/并行/步骤复核/产物测试通过，2 警告，44.80 秒。另 2bb79cd 固定版本全量回归 1335 项通过、109 警告、872.51 秒，覆盖前批代码；本次恢复修改的全量验收单独进行。

证据：[三个原生停止路径](sources/remaining-modifications-20260912/native-lifecycle-3-audit.json)、[实际 worker 崩溃与重启](sources/remaining-modifications-20260912/worker-recovery-live-2-audit.json)。这些验证覆盖本机 Windows、一个共享原生配方及两个记录。跨后端工作流互斥、远程取消和全部服务重启仍需继续验证；也不构成神经保护或完整文献工作流验收。
