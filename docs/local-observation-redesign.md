# 本地数据观测重构方案

状态：本地对象结构、检查覆盖、字段引用 Schema、六组报告和记录详情窗口已实现。新运行使用产物格式 5 / 本地观测结构 2；历史运行保留原快照，可另外生成带检查日期的补充观测。

## 1. 目标与边界

将按 `local-N` 堆积的字符串事实，改为按数据对象组织的有类型记录。报告、三方核对和数据接入从同一套事实投影，避免多份字段分别维护。字段类型、必填项、枚举、单位和引用关系由 Pydantic / JSON Schema 约束；提示词只负责指导解释，不承担数据结构约束。

本地观测回答“文件中实际有什么”；文献和官网回答“资料如何描述”；比较层回答“二者是否相符”；接入层决定“如何处理差异”。不把模型对任务含义的判断写成本地测量，不把可读取、数值有限等基础检查称为信号质量合格。

## 2. 六组内容与阅读顺序

| 分组 | 问题 | 内容与原需求对应 |
| --- | --- | --- |
| 范围与覆盖 | 看了哪些数据，哪些尚未看？ | 数据集入口、本地根目录、扫描范围、选择范围、实际读取范围、失败和跳过对象；对应任务子集、文件与记录统计 |
| 文件与记录组织 | 数据怎么存放，如何定位？ | 目录树、文件清单、辅助文件、记录到文件映射、Subject/Session/Task/Condition/Acquisition/Run、连续/分段/已切 Trial；对应目录、格式、BIDS 根信息和记录结构 |
| 信号与采集 | 每条信号如何采集和编码？ | 原始文件头、原始存储编码/量纲/校准、解码后数组、采样率、通道/导联、参考/接地、设备/电极/滤波；对应采集参数、文件头、数组和通道 |
| 事件与实验流程 | 标记、时间与实际任务如何对应？ | 每个事件的原始标签、起点、时长、样点，辅助事件文件，标记计数、事件序列；任务解释、刺激/间隔/阶段时长在解释与比较层引用这些事实；对应 Trigger 表与完整实验范式 |
| 被试与实验元数据 | 被试是谁，还有哪些背景信息？ | 原始人口学/分组/行为/刺激记录、数据集版本/许可等本地声明及其位置；对应人口学、身份发布与使用限制；目录命名只能证明发现了编号 |
| 统计、差异与待办 | 数据规模、变化和缺口是什么？ | 按选择范围、被试、Run、条件汇总；公共属性与少数差异；读取错误、数值检查结果、未完成检查；对应其他统计以及接入前快照 |

这些分组是阅读和检查维度；底层按对象存储，不为每个分组复制同一条记录。

## 3. 固定产物与对象模型

以 `survey/local-inspection.json` 作为本地观测入口，固定顶层字段：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 本地观测结构版本 |
| `scope` | 根目录、发现范围、选择依据、实际读取对象；原始目录数与成功读取数分开 |
| `scope.inventory_path` | 文件清单路径；固定行 Schema 在 `process/schema.json` 的 `InventoryRow` 中，不在 JSON 中复制全目录 |
| `dataset_metadata` | 本地数据集声明的字段；模型推断及官网值不填入此处 |
| `subjects` | 按被试对象键保存人口学和分组字段；无来源的年龄、性别等为 null |
| `recordings` | 按记录对象键保存文件引用、各层级标识、记录形态、原始头信息、解码数组、采样率、样点数、时长、配置引用及事件表引用 |
| `channel_sets` | 不重复保存的通道集合，保留原始名称和顺序；共享集合键由规范化内容摘要产生 |
| `acquisition_sets` | 不重复保存的采集配置；未知字段仍保留，不能从软件默认值补全 |
| `statistics` | 由对象记录确定性计算的汇总；明确分母和读取覆盖率 |
| `coverage` | 固定检查项登记表，记录检查状态、适用范围、依据、缺口原因 |
| `provenance` | 检查器版本、参数、时间、输入文件哈希与字段定位映射；共享来源与工具调用记录，不给每个标量套完整包装 |

逐文件清单仍使用 `source-inventory.tsv`；高基数逐事件数据放入固定列的 `local-events.tsv`，通过记录键关联。文件格式及字段集合在实施时随版本整体冻结。更复杂的通道级诊断仅在检查器实现后加入版本化契约，不预先制造大量空诊断表。

`recordings` 中单个对象的形状示意（用于说明类型与归属，不是完整 Schema）：

```json
{
  "S001R04": {
    "subject_id": "S001",
    "session_id": null,
    "run_id": "04",
    "source_file": "S001/S001R04.edf",
    "read_status": "readable",
    "storage": {"container": "EDF", "physical_units": null},
    "decoded_signal": {
      "axes": ["channel", "sample"],
      "shape": [64, 20000],
      "dtype": "float64",
      "unit": "V",
      "nonfinite_count": 0
    },
    "sampling_rate_hz": 160.0,
    "duration_s": 125.0,
    "channel_set_ref": "channels-<content-digest>",
    "acquisition_set_ref": "acquisition-<content-digest>",
    "events": {"table": "local-events.tsv", "record_key": "S001R04"}
  }
}
```

原始文件编码、物理单位、采集参考与解码器输出严格分开。不能因为 `get_data()` 返回 V 单位 float64，就声称 EDF 按该类型和单位存储。时间字段统一记录单位与时间原点，保留非整数样点的原始时间，不能通过取整悄悄改写。

## 4. 替代 local-N 的引用机制

记录键采用数据集适配器解析出的稳定对象键，在当前数据集与快照内唯一；避免以扫描序号标识科学事实。调用方引用“快照 + JSON Pointer”，例如：

`survey/local-inspection.json#/recordings/S001R04/sampling_rate_hz`

按属性跨记录核对时，模型可引用注册好的统计字段和对象范围，不再输出 10 个或 100 个流水编号。运行时 Schema 将可选引用限定为实际存在、检查范围匹配的字段。校验器核查引用目标、值类型、单位、来源与对象范围，不能通过字符串查找猜测。

引用定位和取值由代码完成；LLM 不抄写本地测量值。面向用户显示“被试 S001 · Run 04 · 采样率”，底层指针、哈希与检查器信息在溯源详情中展示。

## 5. 检查状态与核对状态分离

每项需求有固定检查键，例如 `signal.raw_header`、`events.timeline`、`acquisition.reference`，不采用每文件一条“需求”的计数方式。

检查状态：

- `observed`：所声明的范围已完成检查并取得值；不代表正确或一致。
- `partial`：只覆盖部分字段或对象，明确成功和未完成范围。
- `not_checked`：未执行；原因区分检查器未实现、尚未执行、超出本轮范围。
- `not_found`：已在明确位置搜索，但没有取得所需内容；不能扩大成全数据集不存在。
- `read_error`：尝试读取失败，保存对象和错误信息。
- `not_applicable`：有依据证明不适用；不能仅因未知而使用。

取值为 null 时必须能从 coverage 找到原因。已测得的零保留为零。`consistent/conflict/unverifiable` 等属于比较层，不能混进采集状态。内容矛盾时保留各来源原值，由比较层登记冲突，不能择一覆盖。

完整性按需求组、对象范围展示，例如“事件时间轴：10/10 条记录已读取；辅助事件文件：0/10 尚未检查”。不把 82 条观测包装成 82 项需求完成。

## 6. 分层执行逻辑

1. 冻结本轮选择与输入快照；扫描目录和文件角色。仅目录枚举成功不能算内容检查完成。
2. 识别可读取的根元数据、数据字典、通道/事件/被试表等辅助文件；先读小型结构化资料，记录来源。
3. 逐记录提取原始文件头和元数据，区分原始内容、解码结果与按命名约定解析的对象身份。
4. 按明确范围读取数组和事件；检查数值有限性、时间界限等基础属性。辅助事件表与 EDF 注释的对齐检查保留覆盖和差异。
5. 聚合公共通道/采集配置，计算汇总与差异，生成 coverage。对同一检查在接入阶段可复用同一函数，但源输入与标准副本分别保存快照。
6. LLM 阅读官网和文献，解释任务、实验范式及资料适用范围。官网指定论文必须跟进读取或明确记录失败；“官网指定参考文献”与“论文内容角色”采用不同字段，不能因为属于系统论文而隐藏引用关系。
7. 比较层按“属性 + 对象范围”对照来源；缺少独立数据集论文时保留可用证据和缺口，不把缺少一类来源机械等同于所有属性均无法核查。
8. 报告从上述记录填模板，先显示范围、共性、差异与未完成项，再展开对象明细与证据；接入决策引用这些事实继续处理。

## 7. 保留、合并、补充和删除

| 调整 | 内容 |
| --- | --- |
| 保留 | 原始路径、逐记录测量、通道顺序、事件原值、输入哈希、资料引用和未知信息 |
| 合并 | 文件头中重复的通道数/采样率与对象字段统一取值；相同通道集合和采集配置只存一次；每记录八行改成一条记录 |
| 补充 | 完整检查清单、字段类型/单位、原始头与解码结果区分、逐事件时间、辅助文件检查、需求覆盖范围、元数据来源和失败原因 |
| 删除 | 无语义的流水号展示、重复展开的通道长列表、拼接成字符串的字典和数组、没有实际检查就认定不存在或不适用的结论 |
| 移出本地事实 | 任务语义、论文结论、来源一致性判断、数据排除决策；分别进入解释、比较和接入层 |

人口学、设备、参考等不是“暂时没值就删掉的需求”；保留在固定检查清单中。新的可选科学指标（如频谱或信噪比）需先定义方法与适用范围，不为填满报告而任意添加或宣称已实现。

## 8. 报告交互

“数据信息”报告先给出范围与关键差异，再提供六个分组导航。记录明细默认一行一个 EDF：被试、Run、采样率、通道数、样点数、时长、事件数、检查状态。选择记录打开侧栏，按信号、事件、元数据分组展示；原始头、通道长列表和溯源信息折叠。

三方对照以“本地观测 / 官方资料 / 官方指定论文及其角色 / 补充资料 / 核对结论”组织，列出实际适用的证据，不要求所有来源都具备每个属性。报告中的“未完成项”始终可见，不藏在长篇总结中。共性按选择范围汇总，少数差异直接点名对应记录。

## 9. 实施顺序与验收

1. 建立新契约、覆盖清单与适配器字段定位，使用现有 10 EDF 验证对象结构。实现未覆盖检查时明确增加检查器，不先把 unknown 改成 completed。
2. 完成本地提取与共享统计，替换 LocalFact 字符串生成；对已实现的辅助文件和原始头检查形成有来源的结果。
3. 更新核对模型的运行时 Schema、引用校验、官方论文身份表达以及下游接入引用。不能只改报告而保留旧数据逻辑。
4. 更新六报告、最终报告和窗口内对象详情。统计报告复用计算结果，不重新独立统计。
5. 推进产物格式版本，从新运行开始使用新结构。旧版本保留旧读取器和原始审计；可投影旧数据的已知字段，但新增需求必须标为未检查，不能伪造历史完成状态。运行中途禁止切换结构。

验收必须覆盖：10 条记录的值与原文件一致；共享通道顺序不变；新增/缺失/损坏记录有清楚的范围状态；混合采样率和记录时长差异可见；事件非整数时间不丢失；原始单位与解码单位可区分；缺失元数据不变成否定结论；错误引用被 Schema/语义校验拒绝；报告共性与逐记录结果一致；历史快照不被覆盖。

## 10. 当前实现与保留事项

- `local_contracts.py` 固定对象字段、17 项检查清单、跨对象引用及统计一致性；`local_observation.py` 在 EDF 解码时提取数据，不另行请求模型填写本地测量。
- 实际存储头保留 EDF 的逐信号单位、数字/物理范围和预滤波文本；解码数组单列类型、维度、V 单位和非有限值数量。相同通道及采集描述通过内容摘要共享。
- `local-events.tsv` 固定六列：record_id、event_index、label、onset_s、duration_s、sample_position。样点位置保留小数。
- `verification_contract(local)` 为每个核对属性生成实际可用指针枚举；不存在本地观测的属性仅允许空引用。代码补齐该属性全部已观测对象。旧 `local_fact_ids` 字段名保留以兼容读取，值从新运行开始为 JSON Pointer；内部 `.facts` 仅作为旧比较接口的临时投影，不写回文件、不送给模型。
- 数据信息报告分六组导航，记录详情在阅读区域右侧展开；长文件头与来源定位继续折叠。统计与最终报告同步采用易读的数值投影。
- 通用 BIDS 根元数据、WFDB `.event` 对照、设备/参考/接地含义、电极坐标、人口学及行为元数据提取尚未实现，固定清单明确列为 `not_checked`。本地事件本身不能确认任务语义。
- 上述“官方指定引用与论文内容角色分开”的调研机制仍是后续工作；本轮不改写既有模型调研结论，也未重新进行外部检索。

真实验收：EEGMMIDB S001–S005 的 Run 4/8，共 10 条记录，300 个原始事件，总时长 1238 秒。160 Hz、64 个解码 EEG 通道，共享同一通道顺序；原始 EDF+C 头有 65 路存储信号（含注释），EEG 原始物理单位 uV，MNE 输出 V。4 条记录为 20000 样点 / 125 秒，其余 6 条为 19680 样点 / 123 秒。输入 SHA-256、采样率、样点、事件计数均与原运行匹配。

已完成运行可在后端目录执行：

```powershell
.venv-eeg/Scripts/python.exe -X utf8 -m app.workflows.local_refresh workspace/training-workflow/workflows/<workflow-id>
```

这会在 `survey/observation-v2/` 原子发布独立补充产物，页面优先显示其中的数据信息报告。原 `local-inspection.json`、调研结论、格式快照和训练包保持原样；补充检查与历史测量不同、运行未完成或补充目录已存在时拒绝发布。新运行始终直接生成新结构，无需执行此命令。
