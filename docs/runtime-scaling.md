# 真实数据规模下的运行规则

## 资源规划

预处理先按全部执行单元估算工作副本及产物空间、逐记录峰值内存，再校验资源。

- 未显式配置上限时，磁盘预算采用输出盘当前可用空间的 85%，内存预算采用当前可用物理内存的 70%。保留部分资源供系统和其他进程使用。
- API 调用方可以通过 `PlanRequest.max_disk_mb/max_memory_mb` 设置更低的上限。空值表示自动探测，不代表无限资源。
- `preprocessing/plan.json` 保存探测值、采用的预算、总空间估算以及每个执行单元的估算。资源估计有余量，不能当作最终产物大小。
- Worker 在执行前复核资源。续跑只计算未完成或校验失败的执行单元；已验证的成功结果复用。
- 资源不足独立于方法编译错误，不反馈给模型修改科学参数。已保存的设计在重试时优先重新编译。

## 数据与执行规模

每个工作副本包含本记录及所需继承元数据。源数据集在任务开始和结束时全量校验，每条记录另做对应文件校验；最终校验失败时不能发布成功结果。取消检查只查询任务取消标记，不反复加载所有已完成产物。

Web 工作流报告已完成/总执行单元，进度轮询只读取聚合状态和数量。命令行默认等待完成；仅显式提供 `--timeout SECONDS` 时限制总运行时长。单次网络调用、科学算子的参数域和有限纠错次数仍有各自约束。

## 模型输入与文献证据

本地观测按相同测量值分组，每组保留所有成员编号；不同采样率、事件分布、失败记录等单独呈现。完整源文件头和逐事件表保存在固定结构的本地记录中。

模型核对合同使用字段判别联合，`local_fact_ids` 必须为空；代码依据比较字段附加全部实测引用并验证关联。模型不再重复输出数千个本地定位符。接入、方案设计和报告解释均使用分组上下文，报告表格仍从完整记录生成。

长文的预览与实际补充阅读片段进入同一个引用目录。每个片段绑定来源哈希及真实字符偏移，筛选后的引用按原文逐字校验。

模型输出被截断时报告输出容量问题，不把不完整 JSON 当成语义错误反复修订。限流、服务端错误、连接及超时最多重试三次，复用相同请求并有限退避；其他客户端错误直接报告。

## 训练交付

训练数组以固定 float32 `.npy` 格式分块写入并回读核验，不在内存中拼接全部 Epoch。按被试采用 70/15/15 的训练/验证/测试比例，以固定种子打乱并按最大余数法分配；至少三名被试时三组非空。一名被试只有训练组，两名被试为训练/测试各一名。

训练示例通过内存映射读取信号，分块计算每个试次、每个通道的对数方差，只保留特征矩阵供模型训练。标准化和模型拟合仅使用训练组。

窗口默认 0–2 秒，支持显式指定负起点或更长窗口，只要求起点小于终点且数值有限；实际可用 Epoch、内存需求和参数合法性由编译与执行检查。

## 格式与历史运行

格式版本为 8。历史产物保持可查看；不同合同版本的未完成运行使用原版本继续或新建运行，不能在重试时混用旧合同与新代码。
